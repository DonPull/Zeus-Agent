# UI/core bridge contract

React calls the Rust core only through `src/bridge/index.js`. SQLite owns durable messages, sequence, visibility, runs and attachment links. Subscribe, hydrate and upsert by message ID/sequence; never create a durable-looking optimistic message. The Phase 3C candidate has one shared browser executor; older recording APIs are read-only adapters. [Current acceptance record](docs/PHASE_3C_WORK_LOG.md).

## Phase 3A attachment APIs

`saveTaskAttachment(taskId, filename, base64Data)` returns an attachment object, replacing the former path string. Its fields are `id`, `task_id`, `filename`, `storage_key`, `mime_type`, `byte_count`, `sha256`, optional `width`/`height`, `created_at`, `status` and `last_delivery`. Treat `storage_key` as metadata; send the stable ID. All internal callers use this contract. Old text-only message callers remain compatible.

Uploads detect and decode actual content. Static PNG/JPEG/WebP images allow 10 MiB and 25 million pixels each. Messages allow eight attachments and 30 MiB total; generic files retain a separate non-image path. Same-name files have distinct UUID directories. Linked uploads are retained; opportunistic cleanup removes at most two unchanged, unlinked uploads older than seven days per upload operation. This is logical identity/integrity validation, not OS-enforced immutable storage or a sandbox.

`sendUserMessage(taskId, content, requestId, attachmentIds = [])` validates task ownership, content integrity, explicit denials and image-route readiness before acceptance. The run, user message and ordered attachment links commit together. Reusing a request ID returns `REQUEST_ALREADY_EXISTS`; it never starts another inference. Empty text is valid with attachments. Preflight failure leaves the input unaccepted.

`onUserMessageAccepted(callback)` returns an unlisten function. Its payload is `{task_id, request_id, message_id}` and is emitted after the acceptance transaction commits. Install it before sending; clear only the matching task/request's captured draft/tray. The send promise resolves after execution, so an inference failure can occur after acceptance. Durable `task-message` events and `getTaskMessages` remain authoritative if an event is missed.

## Explicit chat links

`resolveMessageLink(taskId,messageId,href)` requires a visible stored chat message belonging to that task. It returns either a validated HTTP(S) URL or metadata for an existing regular file within that task's workspace. Relative and app-origin artifact URLs resolve against the task workspace. Encoded filenames are decoded once; Windows canonical local-drive prefixes are normalized. Foreign workspaces, network/device paths, linked ancestors/files and other URL schemes are rejected. It does not read file contents, execute files or grant tool permissions.

`openMessageLink` repeats validation, then opens web URLs through the default OS browser or reveals a file in the OS file manager. All chat Markdown uses explicit click handlers; no link may navigate the privileged app webview. Files first show their name, type, size and location with **Show in folder**. This is not a document preview or download. Streaming links wait for a persisted message. The evaluation-only opener seam records validated intent without opening OS windows; it is absent from the ordinary production binary.

`getTaskMessages(taskId, includeHidden = false)` includes ordered `attachments` on each message. `last_delivery` is a derived latest attempt across reuse, with `state`, `error`, serialized `route`, and nullable `request_id`. It is separate from upload `status: ready`; provider delivery success does not establish comprehension. Re-emitted delivery snapshots retain the message's ID and sequence.

Normal `getTaskMessages` remains master-only. `getTaskDebugMessages(taskId)` explicitly requests hidden messages and all task conversations through the optional `includeAllConversations` backend flag. Debug exports contain the visible master transcript and every stored raw conversation, with message/model/attachment metadata and latest run/usage snapshots. The backend event log remains a volatile 2,000-entry ring per task: restart loses those events, and the export labels that coverage gap. Original image bytes/previews and credential-vault contents are not fetched for the report.

`getAttachmentPreview(taskId, attachmentId)` verifies ownership, containment, denials and SHA-256 before returning a bounded PNG thumbnail data URL. Fetch lazily for image chips. Bytes are transient in preview/provider payloads, absent from persisted chat text. `attachment:<id>` is the stable handle accepted by the `analyze_visual` tool for deliberate follow-up inspection. Legacy path notes are readable history; they are not automatically imported or reconstructed.

Errors carry stable prefixes such as `ATTACHMENT_MEDIA`, `ATTACHMENT_QUOTA`, `ATTACHMENT_CHANGED`, `ATTACHMENT_OWNERSHIP`, `ATTACHMENT_PATH`, `ATTACHMENT_DENIED`, `ATTACHMENT_CAPABILITY` and `ATTACHMENT_EMPTY_ANALYSIS`. Preserve the original provider rejection. A visual tool failure returns `{ok:false,error:{code,message}}` inside the directive result, rather than a successful-looking analysis string. Stop and restart retain cancelled/interrupted delivery evidence.

## Provider and image settings

`fetchModelCatalogue()` returns connection-labelled entries with `connection`, `status`, `models`, `observed_at`, and nullable `error`. Supported connections are `abacus`, `gemini`, `xiaomi` and `local`. Missing credentials/unreachable catalogues have explicit states; a model listing is availability evidence, not a capability guarantee. `fetchAvailableModels()` remains a flattened compatibility wrapper and loses connection identity.

Task and global settings include `model_bindings`, keyed by enabled role (`master`, `worker`, `verifier`, `watcher`, `vision`). Each value contains `connection`, exact `model_id`, `protocol: auto|chat|responses`, `image_input: unknown|supported|unsupported`, and `source`. The compatibility connection `legacy` resolves the former route once; ordinary new hosted selections bind Abacus. A binding must match the role's model ID. Disabled roles have no binding. Task updates are transactional; stale bindings reject the whole update.

`image_delivery: auto|helper` is persisted alongside bindings. Auto sends actual images to a confirmed capable actor; otherwise it requires a configured capable helper. Helper mode explicitly uses that helper even when the actor supports images. Unknown models require a declared capability or capable helper; there is no silent image removal or model/provider substitution. The initial helper call is deterministic. Follow-up tool inspection uses the configured helper, or a capable master when the helper is disabled, through shared permission and cancellation handling.

Existing tasks/defaults preserve legacy provider behavior until explicitly changed, avoiding an unrequested change of billable provider. To use an existing Gemini-named selection through Abacus, select **Abacus** in that role's provider control. Direct Google development still requires its separate Google credential. Protocol and image-support overrides are under **Model input settings**. Credentials stay in the OS credential store, never in bindings or trial manifests.

Usage summaries include `requests_by_connection` alongside actual endpoint origins and roles. Per-request accounting retains the declared binding, resolved protocol and capability provenance; provider credits remain unknown where unavailable. Provider identity is a routing contract. The actor receives configured model/provider/effort metadata, which is configuration evidence rather than independently verified model weights.

## Stabilization policy and error handling

Attachment reads and file tools use the same Windows-aware file-policy identity. Explicit rules retain their task/global specificity and are evaluated before automatic allowances. Local relative/new paths resolve against the task workspace and existing canonical ancestors; workspace containment uses component boundaries. Explicit UNC/device paths are evaluated lexically without network metadata probes and require a matching explicit rule or approval. This is logical authorization, not a race-free filesystem sandbox. Existing explicit-local and legacy-evaluation relaxations remain for the later approval design.

Normal one-time approval APIs remain the only route used by the prepared synthetic diagnostic supervisor. It is controller-owned, task-scoped, restricted to declared bounded native file operations and independent of outcome grading. It never installs persistent rules or broadly approves scripts. Production Smart approvals are not implemented by this controller.

Final-answer preambles remain hidden raw history; one final summary is visible. Ordinary chat can finish without an executable directive. Malformed directives and narrowly detected short action announcements receive bounded repair rather than endless forced continuation. This does not establish semantic task completion. Recoverable render boundaries protect settings/root views; they do not catch native process aborts. Startup changes in-flight ledger rows to interrupted with unknown usage retained.

Cancellation is finalized only at the root send boundary after inner execution unwinds and owned managed-browser cleanup completes. Workers/tool waits propagate `RUN_CANCELLED`. The Stop notice, interrupted plan projection and terminal run/attachment state commit together; repeated finalization is idempotent per run. The UI renders that one backend-owned notice without filtering duplicate text. Permission titles explicitly allow text selection; approval policy/actions are unchanged.

## Phase 3B/3C shared browser APIs

`getManagedBrowserStatus()` reports `route:managed-v1`, saved/default setup and readiness. There is no engine-selection flag. Debug exports include `runtime_at_export` even with no sessions; it describes the exporting process, not all historical runs. Interpreter setup is explicit and frozen per root; see [runtime setup](scripts/browser_service/README.md). `getBrowserSession` is a bounded older-format adapter; the old unpaged gallery API is retired in favor of `listBrowserRecordings`.

`getManagedBrowserSessions(taskId)` returns durable task-owned session snapshots: `schema_version`, session/task/root `run_id`, `generation`, `version`, status/timestamps, runtime/cleanup metadata, `terminal_reason`, `recording_coverage:managed_actions`, and `viewer_available:true`. One root run creates at most one session; data-only scripts create none. A later user turn creates another root/session, while the dedicated task profile can persist site state. Successful root completion is published after joined browser cleanup.

`getManagedBrowserActions(taskId, sessionId, after = 0)` validates task ownership and returns at most 100 journal entries with increasing action `seq`. Continue from the final `seq`. Entries include stable action ID/caller, operation, redacted arguments, authorization reference, status and serialized response. Intent, dispatched, succeeded, failed, denied, cancelled and uncertain states have different meanings. No response means no verified outcome; an uncertain external effect must not be retried automatically under a new ID.

`getManagedBrowserObservation(taskId)` is a controller-side read-only inspection of an existing active owner. It cannot acquire/start a browser or mutate the page. It uses bounded trusted observation and journals the inspection as a controller action. It supplies actual DOM/semantic content and bounded generic mutation-response metadata, not outcome assertions. A missing/closed owner returns a typed error. Passive viewers instead use independently published captures and never enqueue actor observations.

Actors invoke `{"type":"browser_action","op":"navigate","params":{"url":"https://example.com"}}` inside one normal directive block, or use the injected `zeus_browser.call` client in a Python action. Rust derives task/root/caller from the host channel, enforces the existing policy, and serializes mutations with control leases. Workers/scripts release control without closing the root session. Raw CDP, arbitrary service code, profile takeover/extensions, transfers and visible handoff are unsupported. Host Python is not made an OS sandbox by this route.

The `managed_browser_session` message is one durable status projection, reused at the same ID/`seq`. The backend adds optional `projection_version` metadata to both its emitted DTO and hydrated message. Clients reject older versions during event merge and snapshot reconciliation; ordinary messages keep their sequence/visibility behavior. Visibility remains backend-owned. Startup reconciles orphaned sessions and uncertain actions, updating the same durable card. The card distinguishes stopped/error/interrupted/closed and provides Watch/Replay.

`getBrowserCapture(taskId,sessionId)` returns authoritative session/capture versions, freshness/error/coverage and last retained frame. `heartbeatBrowserViewer` has a bounded expiry. `readBrowserLiveImage(...,seq)` returns authorized binary bytes or exact-sequence expiry; it never substitutes another frame. Metadata-only `managed-browser-capture` events are independent of actor I/O/leases. Subscribe before hydrate and reconcile periodically; close/switch discards late work and revokes image URLs.

While viewed, the source and collector target a fixed 125 ms cadence (8 FPS); preview JPEG quality is 80. There is no load-based adaptive throttle. Verified immutable copied bytes remain valid when a newer descriptor arrives. Two rotating source slots and two authorized in-memory frames bound buffering; selected frames alone cross the bridge. Unattended capture remains slower, idle archival remains at most once per ten seconds, and boundary evidence is separate. The freshness badge uses the displayed image's capture time, not the last event. Watch is active-only; normal Replay becomes available after termination when actions exist.

`listBrowserRecordings(taskId,offset)` returns at most 50 managed/older summaries. `getBrowserRecordingPage(taskId,sessionId,after,limit)` returns at most 100 actions and 512 KiB, actual outcomes and before/after frame availability, explicit long-detail summaries and a continuation cursor. `readBrowserRecordingImage` validates owned paths, size, format/dimensions and hash. `exportBrowserRecording` and `deleteBrowserRecordingImages` are terminal-only: full JSONL journal plus relative verified images, or explicit image deletion preserving metadata/user data. Older data remains limited/unverified. Heavy filesystem readers/export/delete use blocking workers, not the UI thread.

`getBrowserRecordingIndex(taskId,sessionId,after)` returns at most 500 small `{seq,op,status,has_image}` entries and a continuation cursor (recordings are bounded at 5,000 actions). Image presence is a navigation hint; the native reader still validates actual bytes. The viewer virtualizes the continuous strip and centers the selection before paint. +/- navigation and playback skip actions without images; exact strip clicks retain access to those actions. Manual navigation pauses playback. Playback defaults to two steps per second, uses a deadline clock and bounded six-image lookahead, and waits for each selected image to decode. There is no fixed maximum requested rate or guaranteed display throughput. Export remains internal diagnostics tooling.

Replay speed is numeric, rounded to tenths, with a minimum positive rate of 0.1 steps/s. Invalid drafts restore the last valid rate. Candidates decode offscreen before replacing the mounted image and its metadata; selection/session epochs discard obsolete work. A delayed seek keeps the previous presentation without a flashing loading overlay; missing evidence still produces an explicit gap. Action/time/image-selector rows reserve stable space, long URLs truncate, and actor identity remains in Details. Zoom centers axes with free space while retaining access to overflowing image origins.

## Chat titles and design previews

`onTaskTitle(callback)` emits `{task_id,title}` after a generated title has committed. Refresh the task list; SQLite remains authoritative if an event is missed. Default new chats request bounded title metadata as part of a normal model response, without another model call. Hidden `title_proposal` messages preserve the metadata; manually named tasks are not overwritten. `renameTask` marks the title manual atomically. Action-plan payloads include optional `steps_source` (`explicit` or `markdown`); explicit structured statuses remain authoritative.

`ui_showcase` messages are explicitly stored synthetic design examples. Their card payloads render inert previews, not real permission/run/browser entities. The showcase composer is read-only and `sendUserMessage` rejects it before accepting a run. The maintainer CLI inserts the requested gallery idempotently into an existing owned database. [Decisions and validation](docs/CHAT_WORKFLOW_REFINEMENT.md).

`type_text` sends a complete string with real keyboard events in one action. `fill` remains preferable for conventional inputs. `wait` supports text/value/data-or-aria attribute/enabled/disabled checks. Interactions accept `ready` and `expect` checks with optional 0–2,000 ms settling under one action timeout. Failed postconditions produce `BROWSER_OUTCOME_UNCONFIRMED`; partial keyboard input produces `BROWSER_INPUT_UNCERTAIN`. Both journal **uncertain**, with no automatic repeat. Service `timing_ms` separates before capture, execution and after capture; it excludes provider/approval/queue time. See the runtime guide for examples and hydration limits.

Explicit screenshots alone enter `browser_visual_deliveries` and reach the calling role's declared direct/helper route once. `getBrowserVisualDeliveries` exposes the last 100 delivery states/provenance. Unknown/unsupported routes preserve text and explicit failure; passive viewers trigger no inference. `inspect` uses bounded trusted fixed code, not caller JavaScript. [Final bounds and decisions](docs/PHASE_3C_WORK_LOG.md).

Protocol, observation, action/queue, artifact and export bounds are documented in [the delivery record](docs/PHASE_3B_WORK_LOG.md). Known sensitive field names are masked and network bodies/headers are not retained; page text, values and images can still contain private content. Auth tokens are transient. Debug browser exports are separately bounded/labelled; the full stored chat remains in the debug report. Session closure and action success are independent of semantic goal completion.
